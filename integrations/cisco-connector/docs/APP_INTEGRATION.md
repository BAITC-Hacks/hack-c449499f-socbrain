# Передача записи в приложение

## SOCBrain в этом репозитории

Готовый приёмник находится в [backend/INGEST.md](../../../backend/INGEST.md).
Он реализует POST `/api/recordings` и принимает контракт `gateway` из таблицы ниже.
Параметры для worker и приёмника на одном Linux-хосте:

```dotenv
APP_UPLOAD_URL=http://127.0.0.1:8020/api/recordings
APP_CONTRACT=gateway
APP_API_KEY=<то же значение, что SOCBRAIN_API_KEY у приёмника>
APP_ALLOW_HTTP=true
APP_IDEMPOTENT=true
```

Worker использует host network. Для другого хоста задайте его внутренний HTTPS-адрес.
Коннектор отправляет Idempotency-Key для экземпляра встречи, SOCBrain проверяет SHA256,
название и дату и возвращает прежний id при повторе. `APP_IDEMPOTENT=true` разрешает безопасные
повторы после сетевых ошибок, 429 и 5xx. Включайте его только для приёмника с такой гарантией.
GET `/api/recordings/{id}` на порту приёмника возвращает статус и локальный транскрипт.
Фронтенд SOCBrain в текущем репозитории статический и к этому новому API ещё не подключён.

Ассистент отправляет **завершённый WAV** multipart/form-data по APP_UPLOAD_URL.
Сначала WAV закрывается и проверяется, затем открывается для HTTP-загрузки.
Проверка подтверждает наличие RTP и аудиоданных; качество/разборчивость речи оценивается приложением.

## Рекомендуемый контракт gateway

```dotenv
APP_UPLOAD_URL=https://protocol.company.local/api/recordings
APP_CONTRACT=gateway
APP_API_KEY=<ключ приёмного gateway>
```

| Поле | Значение |
|---|---|
| file | WAV, audio/wav |
| title | Название из календаря |
| meeting_date | Дата встречи в её часовом поясе |
| participants_notified | true |
| source | cms |

Ответ: HTTP 2xx и JSON `{"id":"<идентификатор записи>"}`.
В Protocol AI этот контракт реализован сервисом meeting-gateway. Он ставит файл
в очередь только после полного сохранения. Запустите этот gateway рядом с приложением
по его README; отдельный Cisco-коннектор не разделяет с приложением SQLite.

## Совместимый контракт protocol-ai

Для приложения с POST `/api/meetings` задайте `APP_CONTRACT=protocol-ai` и соответствующий
APP_UPLOAD_URL. Поля: file, title, meeting_date, consent=true. Ответ также должен содержать id.
Используйте этот вариант только если приложение гарантирует постановку в очередь после
сохранения файла. В исходном приложении Protocol AI обнаружена ранняя постановка в очередь;
для него предпочтителен gateway. Сам коннектор эту чужую очередь не изменяет.

Для HTTP внутри доверенной изолированной сети дополнительно задайте APP_ALLOW_HTTP=true.
Это явная настройка; TLS для CMS/Scheduler от этого не отключается.
Worker с host network обращается к реальному адресу приложения/хоста, не к Compose DNS-имени другого проекта.

## Проверка и ручная отправка

Для проверки найдите задание со статусом delivered и его result.id, затем проверьте запись
в приложении. `delivered` не означает завершённое распознавание.

После проверки отсутствия дубликата администратор может отправить сохранённый WAV:

```sh
curl --fail-with-body "$APP_UPLOAD_URL" \
  -H "X-API-Key: $APP_API_KEY" \
  -F "file=@recording.wav;type=audio/wav" \
  -F "title=Совещание" -F "meeting_date=2026-09-23" \
  -F "participants_notified=true" -F "source=cms"
```

Не используйте произвольную текущую дату вместо даты исходной встречи.
При ручной отправке журнал коннектора автоматически не обновляется.
Webhook с итоговой расшифровкой и изменение приложения не входят в этот репозиторий.
