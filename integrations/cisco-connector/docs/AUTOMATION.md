# Автоматизация и эксплуатация

## Последовательность

1. Worker читает календарь CMS Scheduler на ближайшие 24 часа, включая идущие встречи.
2. Оставляет только комнаты из ASSISTANT_SPACES; проверяет UUID, время и часовой пояс.
3. Сохраняет экземпляр встречи в SQLite. Ключ строится из meeting ID и recurrence/start.
4. В назначенное время читает SIP URI coSpace и запускает отдельный процесс PJSUA2.
5. Ассистент звонит в комнату, записывает входящий аудиопоток и не отправляет микрофон.
6. По завершении SIP-вызова или запланированного времени закрывает WAV.
7. Только после подтверждённого SIP-соединения, получения RTP и закрытия WAV отправляет файл.
8. Сохраняет ID записи, возвращённый приложением.

Точность начала ограничена интервалом опроса, временем HTTP и SIP-соединения.
Сбор событий Cisco/ASR в реальном времени пока отсутствует. Встречи полного дня и
неоднозначное/несуществующее локальное время перехода DST отклоняются с диагностикой.
Правило rrule не разворачивается повторно: экземпляры возвращает CMS Scheduler.

## Изменения расписания

До начала обновления времени/названия применяются при следующем успешном чтении.
Исчезновение встречи из полного снимка отменяет ожидающее задание; если ассистент уже
подключён, он завершает только свой вызов. Саму конференцию коннектор не удаляет.
Перенос активной встречи на будущее также отключает ассистента.
Продление уже идущей встречи не продлевает предельное время дочернего рекордера:
в этой версии он остановится в первоначально переданный срок.

При ошибке/обрезанном календаре новые подключения в этом цикле не запускаются.
Уже идущая запись продолжается до своего предельного срока. Отсутствие календаря не
считается доказательством отмены. Если одновременно начинаются две встречи, одна записывается,
вторая получает skipped. Для параллельных конференций нужны отдельные ассистенты с
непересекающимися allowlist, отдельными volume и SIP/RTP-портами.

## Состояния задания

| Статус | Значение |
|---|---|
| pending | Ожидает времени начала |
| recording | Запущен SIP-процесс; само состояние не гарантирует подключение |
| recorded | Закрытый файл подтверждён рекордером, ожидает доставки |
| uploading | Выполняется HTTP-загрузка |
| delivered | Приложение приняло файл и вернуло id; ASR ещё может выполняться |
| cancelled | Ожидающая встреча отсутствует в успешном снимке календаря |
| missed | Запланированное время завершилось до подключения |
| skipped | Конфликт с другой встречей |
| failed | Ошибка SIP/медиа/локального файла либо прерванный worker |
| delivery_unknown | Приложение могло принять файл, результат требует проверки |

`GET /api/assistant/status` показывает heartbeat, последнее чтение календаря и ошибку.
`GET /api/assistant/jobs` показывает журнал; `recording` означает попытку подключения,
подтверждение полученного аудио появляется только после завершения процесса.

## Сбой и повторная отправка

Для включённого `APP_IDEMPOTENT=true` (готовый SOCBrain receiver) записи автоматически
повторно отправляются с тем же Idempotency-Key после сетевых ошибок, 429 и 5xx.
Незавершённая загрузка при перезапуске возвращается в очередь recorded.
Описанный ниже консервативный режим применяется при `APP_IDEMPOTENT=false`.

Автоматический повтор безопасен только при ConnectError до отправки запроса.
После таймаута чтения, обрыва передачи, неправильного ответа или HTTP-ошибки повтор не делается:
в принимающем приложении нет гарантированной идемпотентности, возможен дубликат.
Проверьте наличие записи в приложении; если её нет, отправьте сохранённый WAV вручную
по [инструкции интеграции](APP_INTEGRATION.md). Файлы не удаляются после отправки.

После перезапуска незавершённые записи помечаются failed, незавершённые загрузки —
delivery_unknown. Повторного звонка для того же экземпляра встречи нет.
Автоматическое восстановление записи с места обрыва не реализовано.

## Остановка и перенос

```sh
docker compose stop assistant
docker compose stop connector
```

Остановка worker закрывает его активный SIP-вызов. Файл остаётся в volume.
Для копирования данных остановите оба сервиса и сохраните volume connector-data:
SQLite, WAV и JSON следует переносить вместе. `docker compose down` сохраняет volume;
не добавляйте `-v`, если записи нужны.

API и worker healthcheck показывают живой процесс/heartbeat. Они не подтверждают
доступность Cisco, включённую автоматизацию или успешное распознавание в приложении.
