# Очереди, статусы и восстановление

## Cloud Recording

`pending → processing → delivered`. Временная ошибка переводит задание в `retry`; после восьми
неудачных попыток — в `failed`. При аварийном перезапуске `processing` возвращается в `retry`.
Один `meeting UUID + recording file ID` создаёт только одно задание.

## RTMS

`pending → running → stopping → delivered`. Если live-транскрипт сохранён, но WAV отсутствует или
не доставлен, поток получает `finished` с пояснением. Ошибка подключения SDK даёт `error`.
После перезапуска `running` возвращается в `pending`: worker пытается подключиться с сохранённым
payload, пока Zoom stream ещё действителен.

## Календарь

Обновляется отдельно от очереди записей. Ошибка одного пользователя не удаляет его предыдущий кеш
и не мешает обновлению остальных пользователей.

SQLite и медиа лежат в volume `zoom-data`. Файловая блокировка допускает только один cloud worker и
один RTMS-worker на volume. Текущая версия рассчитана на один хост; горизонтальное масштабирование
потребует внешней БД и распределённой очереди.
